## Owner decisions taken on 2026-10-03

- The always-run guard is `on-exit` (was `defer`). `on-failure` runs on every non-success exit
  including cancellation. `on-cancel` stays and runs in addition on cancellation.
- Co-Forth: a name bound to a callable is applied when written, whether `:` defined it or a typed
  local holds it. `' name` pushes it without applying. `call` applies an unnamed callable on the
  stack and is a reader word, not a prelude operation.
- A temporary passed to a borrowing parameter in a tail call is adopted by the callee frame.

- `value`, `state`, `stack`, `effect`, `arg`, `region`, `infer`, `plain`, and `some` stay reserved.
- Callable types have one source spelling: `callable<(parameters) -> result ! contract>`.
- Priority stated by the owner: avoid reworking the interpreter. Finding 68 in the ledger orders the
  remaining runtime gaps by that risk; work them in that order before the static checker.

- The owner wants the language defined so three unrelated syntaxes can spell it and cross-call.
  Notes for a D-flavoured C-like surface are in `FINCH_LANGUAGE_DESIGN.md` ("A third, C-like syntax
  as a wart detector") and finding 70. It is a design test, not scheduled work. It asks for finding
  69 (reflection records) and structured type nodes in the AST.

- IR: build on the implemented IR version 5 (`crates/finch-vm-core/src/ir.rs`) as version 6 with
  additions; do not design an unrelated IR. Ownership is proven at compile time and erased: the IR
  carries explicit drops and slot references for exclusive borrows, and only `Shared` owners count
  references at runtime. Calling C functions matters; embedding Finch in other hosts matters less.
- Done under that decision: the static ownership pass and IR version 6 with its lowering, verifier,
  and executor (finding 72). The Rust crates are unchanged; extending `finch-vm-core` and
  `finch-vm` to version 6 is implementation work against `semantics/ir.json` and the vectors.

- Browser target: the default `int` is narrower there, target constraints flow through the compiler
  so bad integer coercions are compile errors, and libraries get a compile-time hook to specialize
  per CPU (finding 74). Finding 75 in the ledger is the single list of open questions and unfinished
  work; keep it current.

- The original purpose is an LLM-driven REPL: effects are events to the host, capabilities are
  granted or denied by it (also at compile time), and a program's required capabilities are known
  before it runs so the user can be prompted. Native and JavaScript output must not carry that
  mediation. Finding 76 records what is missing: the manifest and admission step, session turns,
  compile-time grants, and a "direct" effect binding beside the "mediated" one. Manifest, admission,
  turns, compile-time authority (text only), and the direct binding are done. Redefinition
  shadowing was decided without the owner and needs confirming.
- Multidimensional fixed arrays must be one contiguous block; layout, per-dimension bounds checks,
  and equality are unspecified (finding 77).

- Aggregate results are returned in caller storage through a hidden pointer, as in D
  (SPECIFICATION section 16, finding 79). Decided by the owner.
- Local types that can be returned and not named outside (Voldemort types) are wanted
  (SPECIFICATION section 9, finding 80). Not in the executable core, which rejects any nested
  declaration with `F-DIAG-NESTED-DECLARATION`; that code is the core's limit, not a language rule.

## Second hostile round (same day)

An independent review found 20 problems; each was reproduced first. Finding 78 lists what was
fixed. In short: drops at control-flow joins and across `try` now agree between the rule machine
and the IR (the static pass annotates `join_drops` and `unwind_drops`, and `execute` runs the
static pass itself when handed no program); tail calls forward adopted values (`forward` on
`tail_call`); `return` in a `try` or fiber body and handler arms are not tail position; the fiber
resume binding owns each step input; the request instruction carries a verified `static` claim;
the scheduler's `names` needs the header and there are `uses-members`, `embeds`, and
`reflects-members` kinds; contract axis rules are enforced in the frontends.

Decided and implemented after that round (DESIGN_REVIEW finding 81 holds all 19 decisions): the
`fiber (reply : T) body` form and `step` are removed everywhere. A function whose own body
contains `yield` is a generator; calling it makes a dormant fiber that is a single-pass range
(`empty?`, `front`, `pop-front`, `reply`, `start`); `yield` evaluates to an option of the
generator's own parameters; dropping a handle cancels the fiber and runs its cleanup at the drop.
Not done from finding 81: `foreach`, `defer` for non-generators, `spawn` over a scheduler written
in the language with the task self-reference and the unread-failure event, concept conformance and
prelude signatures for the range operations, tuples, generator lambdas through closure values.
Finding 81 also lists five choices made without the owner. A local type
takes what it needs through its constructor; no hidden context, no capture list.
Still open with the owner: the resume binding rule versus `yield` returning the input owned;
whether local functions are capture-free functions or named closures. Not fixed: a catch binder has no static type; the Co-Forth reader
enforces several restrictions section 3.5 does not state (listed in finding 78).
